# 勉強法実験アプリ — 2週間開発スケジュール v2.0

- 開発期間：14日間
- 開発人数：2人
- 開発方式：AIコーディング中心
- 目標：Day 7までにMVP完成、Day 10までに追加機能完成

## 1. 開発体制

### 担当A：AIコーディング・実装担当

AIコーディングツールを活用し、アプリの実装を進める。

- AIへの実装指示
- コードの生成・修正
- 機能の実装
- エラーの解消
- GitHubへのコード反映
- Vercelへのデプロイ

### 担当B：確認・テスト担当

実装された機能が仕様どおり動作するかを確認し、改善点を整理する。

- 実装内容と定義書の照合
- 動作確認
- バグの発見・再現手順の記録
- UI・UXの確認
- 改善点の提案
- テストケースの作成
- 発表準備

### 開発サイクル

1. 担当AがAIコーディングで機能を実装
2. 担当Bが実際に操作して確認
3. 担当Bがバグや改善点を報告
4. 担当AがAIを使って修正
5. 担当Bが再確認

このサイクルを機能ごとに繰り返す。担当Bは、担当Aの実装中に次の機能のテスト項目を準備する。

## 3. 開発マイルストーン

### Day 3：学習まで動く

ユーザーが勉強法を選択し、英単語を使って5分間学習できる。この時点ではテストや結果画面は未完成でもよい。

### Day 5：実験を最後まで体験できる

次の一連の流れが動作する。

ホーム → 勉強法選択 → 結果予想 → 学習A → テストA → 学習B → テストB → 結果比較

### Day 7：MVP完成

実験開始から結果表示までの一連の体験が安定して動作し、実験結果を保存して後から確認できる。

### Day 10：追加機能完成

翌日テストと直後・翌日の結果比較が動作する。

### Day 14：最終完成

アプリを公開し、発表できる状態にする。

## 4. 確認担当の具体的な作業

### 4.1 機能テスト

| 機能 | 確認内容 |
|---|---|
| 勉強法選択 | 2種類を正しく選択できるか |
| 結果予想 | 選択した勉強法が保存されるか |
| タイマー | 5分間正しく計測されるか |
| 確認テスト | 10問すべて表示されるか |
| 自己採点 | 回答が正しく記録されるか |
| 正答率計算 | 7問正解なら70%になるか |
| 結果比較 | 2種類の結果が正しく表示されるか |
| データ保存 | 再読み込み後も結果が残るか |
| 実験履歴 | 過去の結果を確認できるか |
| 翌日テスト | 翌日以降に再テストできるか |

### 4.2 異常系テスト

通常の操作だけでなく、想定外の操作も確認する。

- 勉強法を1種類しか選ばずに進もうとする
- タイマー中にページを再読み込みする
- テスト途中でブラウザを閉じる
- 実験途中でホームに戻る
- 保存データが存在しない状態で結果画面を開く
- スマートフォンで操作する

### 4.3 UI・UX確認

- 次に何をすればよいか分かるか
- ボタンの意味が明確か
- 文字が小さすぎないか
- スマートフォンでも操作しやすいか
- 結果の違いが直感的に理解できるか
- 実験が長く感じられないか

## 5. バグ報告のルール

確認担当は、発見した問題をGitHub Issuesなどに記録する。

報告内容：タイトル（問題を簡潔に説明）、再現手順（どの操作で問題が起こるか）、期待する動作（本来どう動くべきか）、実際の動作（現在どうなっているか）、優先度（高・中・低）。

| 優先度 | 内容 | 対応方針 |
|---|---|---|
| 高 | 実験を最後まで進められない、データが消える | 最優先で修正 |
| 中 | 一部の機能が正常に動作しない | MVP完成前に修正 |
| 低 | 見た目や細かな操作性の問題 | 時間があれば修正 |

## 6. 遅延した場合の対応

### 1〜2日遅れた場合

Day 8〜10をMVP開発に使用し、翌日テストの実装を延期する。

### 3〜4日遅れた場合

翌日テスト、直後・翌日の比較、履歴詳細、細かなUI改善を削減し、実験の基本フローを優先する。

### 5日以上遅れた場合

以下の機能に絞り、最小限の実験体験を完成させる。

- 勉強法選択
- 実験前の予想
- 学習タイマー
- 自己採点式テスト
- 正答率の比較

## 7. 毎日の進め方

1. **作業開始時（10分）**：2人で当日の実装内容と確認項目を共有する。
2. **実装・確認**：担当AがAIコーディングを進める。担当Bは前日までに実装された機能のテストや、次に実装する機能の確認項目を準備する。
3. **機能完成時**：担当Aが担当Bに動作確認を依頼する。担当Bは実際に操作し、問題点を報告する。
4. **作業終了時（10分）**：完成した機能を確認し、未解決の問題を整理して翌日の作業内容を決める。

## 8. 最終方針

AIコーディング担当と確認担当が協力し、実装と検証を短いサイクルで繰り返す。確認担当は仕様との整合性・動作の正確性・ユーザー体験の品質を担う。Day 7でMVPを完成させることを目標とし、進捗に応じて追加機能を調整する。最終的には、2週間以内に実際に利用できるWebアプリケーションを完成させる。
